## 현재 진행 상태

**최신 2026-09-30:** 실제 GPU cache 진단 원본(JSON 170,747 bytes)을 받아 code/lock·실행 설정·40개 위치·28개 층 cache 길이·내장 Q manifest를 검토했다. 정밀도 의존적 차이의 근거는 유지하며 기존 BF16 관문은 실패다. 다음은 결과를 보기 전에 고정한 development 8문항×최대32토큰의 정책 수치 audit이다. [고정 절차·실행](session02/06_numerical_audit.md)을 따른다. 30개 CPU tests 통과, 신규 GPU audit 대기. 본 생성 관문/v0.2.1은 유지, 02 미완료·03 비활성·교수 실제 PASS 미확인. 아래 내용은 진행 이력이다.

2026-09-29: 01 문헌·H1·제안서는 완료했다. 사용자가 “승인 했다는 전제로 우선 진행해줘.”라고 지시하여 승인 가정으로 02에 진입했다. 교수님 실제 PASS는 여전히 미확인이다. 02 구현·19개 core tests·작은 Qwen2/GPTQ CPU 검증과 모델/데이터 분할 고정은 완료했고, 실제 1.5B/GPTQ·RTX 4090·긴 context 검증이 남았다. **02 전체 미완료**이며 [현재 인계](handoffs/02_target_gpu_pending.md)를 따른다.

02-2 업데이트: 실제 GPU 접근과 신규 로그는 아직 없다. 자산 고정값 덮어쓰기 방지, 장비 preflight, 실패 시 로그 묶음, 합성 긴 context 검사를 추가했다. 24개 CPU 검사는 통과했으나 실제 1.5B/4090 통과로 간주하지 않는다. 03 인계는 계속 비활성이다.

10/12는 강한 일정 제약이다. 승인 지연·처리량 부족·관문 실패가 있으면 마감 목표와 연구 범위를 재계산한다. 달력상 날짜가 지났다는 이유로 단계 완료를 표시하지 않는다. 논문 개요와 근거 정리는 앞 단계부터 축적한다.

## 시작·종료 절차

새 세션에서는 `PROJECT_STATUS.md`, 이 운영표, 최신 인계 문서, 관련 프로토콜을 먼저 읽는다. Git 최신 상태와 사용자가 전한 수정사항을 맞춘 뒤 해당 단계의 작업을 시작한다.

단계를 마칠 때 다음을 기록한다.

1. 완료한 작업과 산출물 경로.
2. 실제 증거를 포함한 GO/HOLD/STOP 또는 다음 단계 판정.
3. 결정한 내용, 여전히 미정인 내용, 교수 승인 상태.
4. 프로토콜 버전·코드 커밋·데이터/환경 revision 등 재현에 필요한 식별자. 미확인 값은 미확인으로 남긴다.
5. 다음 세션 이름·목표·첫 작업·복사할 시작 메시지.

`PROJECT_STATUS.md`와 `research/DECISIONS.md`를 갱신하고, `research/handoffs/`에 `<현재번호>_to_<다음번호>.md`를 남긴다. 저장소 반영 후 실제 커밋과 원격 상태를 확인한다. 마지막에는 다음 문장을 사용한다.

> 현재 단계 완료. 다음 세션으로 넘어갈 시점입니다. 다음 세션: **[이름]**. 아래 시작 메시지를 새 세션에 붙여 넣어 주세요.

이 안내는 진행 중인 대화에서 완료 조건을 확인했을 때 제공한다. 새 세션 개설이나 별도 시각의 자동 알림을 설정한 것으로 해석하지 않는다.

## 한 단계가 길어지는 경우

같은 단계에서 맥락이 지나치게 길어지면 `QuantSplit 02-2 — 4-arm 구현·평가 검증 이어서`처럼 이어지는 세션을 사용할 수 있다. 이때는 **단계 미완료·대화만 전환**이라고 표시하고 남은 관문을 보존한다. 해결되지 않은 구현 오류나 승인 대기를 다음 단계로 넘겨 숨기지 않는다.

사용자가 현재 단계 밖의 새 작업을 요청하면 그 요청을 반영해 운영표와 상태를 갱신한다. 계획 자체를 변경 불가능한 승인 절차로 사용하지 않는다.
