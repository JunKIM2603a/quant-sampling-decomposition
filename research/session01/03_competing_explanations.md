2026-09-29 KST. 아래는 설계이며 실행 결과가 아니다. 네 arm의 비교만으로 모든 미시적 경로가 식별되지는 않는다. 추가 대조가 끝나지 않으면 그에 의존하는 강한 설명을 쓰지 않는다.

## PASS 이후 02단계의 필수 구현 검사

1. F=Q, 같은 prefix·난수에서 네 분포와 token trace가 일치하는지 확인한다.
2. top-p=1에서 후보 집합을 허용 vocab 전체로 직접 설정한다. FF=FQ, QQ=QF를 분포/trace로 검증한다. 부동소수점 누적합으로 일부 토큰이 누락되지 않게 한다.
3. cache를 쓴 forward와 전체 prefix 재계산의 logits 차이를 정해진 tolerance로 확인한다. generated token을 두 cache에 넣고 arm간 cache가 섞이지 않는지 감사한다.
4. FF/QQ가 같은 양자화 가중치·prompt·EOS의 독립 기준 구현과 분포 수준에서 맞는지 확인한다. RNG 구현이 다르면 token-by-token 일치를 자동 요구하지 않는다.
5. 동일 난수 key가 batch 크기·문항 순서에 의존하지 않는지 확인한다. 비결정성이 있으면 원인·크기를 기록한다.
6. 특수 토큰, boxed parser, cap 종료, 빈 후보집합, p=1, 확률 동률 경계를 synthetic 예제로 검증한다. 실제 모델 검사는 교수님 PASS 후다.

## 추가 실험의 우선순위와 발동 조건

- **항상 기록:** 네 arm의 정확도·소비량·cap·완결답, 동일-prefix mask 크기/유지 질량/종료 토큰 포함 통계. 추가 전체-vocab 로그를 매 토큰 저장하지 않는다.
- **긍정 결과의 해석을 강화하려면:** QK 및 QQ-E/QF-E를 다음 고정 프로토콜에서 우선 시행한다. QK의 비슷한 점추정치를 동등성이라고 부르지 않는다. 이 대조를 못 하면 ‘BF16 후보집합의 토큰 정체성이 원인’ 또는 ‘분기 표지 복원이 원인’이라고 쓰지 않는다.
- **작은 효과 상한을 기여로 쓰려면:** 원 현상과 실제 mask 변경·질량 변화·구현 타당성을 확인한다. 변화 자체가 거의 없다면 ‘해당 조건의 support 변경이 작다’로 한정한다. 한 양자화·한 데이터의 작은 상한을 모든 sampler의 한계로 일반화하지 않는다.
- **확장:** 주 결과와 예산 확인 후 MATH-500 또는 별도 양자화 조건 중 질문을 가장 잘 구분하는 하나를 먼저 고정한다. 7B는 자동 필수가 아니다. 설정 전 조합 전체를 실행하지 않는다.

E는 실제 generation EOS ID와 reasoning-end token ID의 집합으로 한다. reasoning-end가 다중 토큰이면 단일 ID 합집합으로 대체하지 말고 구현 가능성을 재검토한다. 이 처리는 02에서 tokenizer를 확인하기 전에는 완료로 표시하지 않는다. QQ-E와 QF-E는 각자 생성한 prefix를 사용한다.

추가 대조의 문제 집합·seed·cap·효과 기준·보정 family는 해당 결과를 보기 전에 동결한다. 4-arm 주 결과를 본 뒤 설계한 분석은 새 확인 표본이나 독립 seed의 별도 확인으로 구분하고 원 주검정으로 소급하지 않는다.
