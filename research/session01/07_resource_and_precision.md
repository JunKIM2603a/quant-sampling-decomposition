# 계산 예산과 정밀도 — 제출 단계 점검

2026-09-29 KST. 모든 숫자는 **명시한 가정의 계산**이다. 실제 모델 출력·처리량·GPU 사용 가능 시간을 측정한 결과가 아니다.

## 정확도 비열등성은 자동으로 확보되지 않는다

단일 seed의 paired 정오답 불일치율을 q, 실제 정확도 차이를 0이라 놓으면 차이의 SE≈sqrt(q/n)이다. n=1,319, 허용 손실 0.03, 단측 α=0.05인 정규 근사에서 다음과 같다. 2-seed 계획의 정확한 검정력을 나타내지는 않는다.

| 가정한 q | SE(%p) | 단측 95% 오차폭(%p) | 실제 차이=0일 때 근사 검정력 | 80% 검정력에 필요한 n 근사 |
|---|---:|---:|---:|---:|
| 0.10 | 0.87 | 1.43 | 96.4% | 687 |
| 0.20 | 1.23 | 2.03 | 78.6% | 1,374 |
| 0.30 | 1.51 | 2.48 | 63.5% | 2,061 |
| 0.50 | 1.95 | 3.20 | 45.9% | 3,435 |

계산식: margin=z_0.95·sqrt(q/n), power≈Phi(0.03/sqrt(q/n)−z_0.95), n_80≈(z_0.95+z_0.80)^2 q/0.03^2. 분석 계산만 실행했으며 모델 평가가 아니다. 실제 정확도 차이가 −1%p이면 필요한 여유는 3%p가 아니라 2%p여서 더 어렵다.

파일럿에서는 문제별 A 차이의 분산 및 C_0.50/C_0.20의 공분산을 사용한다. 다음은 결과를 낙관하는 예측이 아닌 설계 능력 점검이다.

- 지지 시나리오: R=0.80, 정확도 차이=0.
- 작은 효과 상한 시나리오: R=0, 정확도 차이=0.
- 민감도: 파일럿 분산의 1.5배, 예상 Delta의 절반인 조건에서도 구간 폭을 계산한다.
- 두 시나리오에서 목표 결론을 각각 80% 이상 판정할 능력이 있는지 평가한다. 공동 지지 확률은 상관을 보존한 문제 수준 시뮬레이션으로 평가하며, 각 endpoint의 개별 80%를 공동 80%로 대체하지 않는다.

미달이면 HOLD하고 범위·예산을 재검토한다. 예상효과를 파일럿의 좋은 점추정치로 바꾸거나 3%p를 느슨하게 해 통과시키지 않는다. 다만 이 설계상 시나리오에서의 검정력은 실제 H1이 참일 확률이 아니다.

## 10/12까지의 비용 계산

기본 주 실험은 1,319문제 ×4 arm ×2 seed =10,552회 생성이다. 모든 arm 평균을 3,000토큰으로 가정하면 총 31,656,000토큰이다. 평균 3,000은 측정값이 아니다.

| GPU당 완성된 4-arm 경로의 유효 처리량 | 주 실험 합산 GPU-h | 30% 여유 포함 |
|---|---:|---:|
| 30 output tok/s | 293.1 | 381.0 |
| 60 output tok/s | 146.6 | 190.5 |
| 100 output tok/s | 87.9 | 114.3 |

F/Q forward 두 번, 두 cache, sorting, sampler, 기록 비용을 포함한 실제 end-to-end 유효 output tok/s를 사용한다. FF/QQ에서 한 모델만 돌리는 최적화가 검증되면 arm별 소비량/처리량을 합산한다. 단일 모델의 광고 처리량을 적용하지 않는다. calibration·구현·pilot·추가 대조·재현 비용은 표에 포함되지 않는다.

예를 들어 190.5 GPU-h는 GPU 두 장이 각 12h/일 사용 가능하면 약 7.9일, 각 24h/일이면 약 4.0일이다. 사용자의 하루 가용 시간은 **미확인**이다. 10/5 파일럿 완료 후 10/10 주 실험 종료는 앞의 12h 가정에서 맞지 않는다.

1.5B에서는 한 GPU에 F/Q를 함께 적재하고 두 GPU에 서로 다른 문제를 배치하는 구성을 우선 검토한다. 가중치 외에 긴 두 KV cache와 여유 메모리가 필요하므로 적재 가능성을 보장하지 않는다. 7B 두 BF16 모델을 한 24GB GPU에 올리는 계획은 채택하지 않는다.
