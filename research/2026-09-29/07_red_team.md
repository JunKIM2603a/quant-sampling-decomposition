# 적대적 검토와 주장 제한

이 문서는 후보를 살리기 위한 해명이 아니라, 진행하면 안 되는 조건까지 포함한 검토다.

| 예상 반론 | 판단과 조치 |
|---|---|
| “양자화 후 길이가 늘어나는 것은 이미 알려졌다.” | 맞다. 그것을 H1이나 핵심 기여로 삼지 않는다. 기여는 확률/후보 집합 교환에 따른 정량적 분해다. |
| “ReSET도 top-p를 조정했다.” | 맞다. 단순 튜닝과 다른 실험이라는 것을 방법 표로 보여야 한다. ‘양자화와 샘플링을 처음 연구했다’고 쓰지 않는다. |
| “greedy에서도 증가하는데 왜 후보 집합을 보나?” | 보편 원인 가설은 기각해야 한다. stochastic 조건에서 추가로 얼마나 복구되는지라는 제한된 질문만 남는다. |
| “BF16 mask는 oracle이라 실용성이 없다.” | 맞다. 진단 실험이다. 성공해도 배포 가능하거나 더 빠르다는 결론은 없다. 실용 방법 개발은 별도 검증이다. |
| “교환 조합은 실제 시스템에 없는 인위적 정책이다.” | 맞다. 개입 효과는 식별하지만 자연적 원인 비율은 아니다. 두 방향 교환과 상호작용을 함께 공개한다. |
| “분모가 작으면 복구율이 폭발한다.” | 원 현상 재현 관문과 Delta 구간을 요구한다. 불안정하면 비율 대신 토큰 단위 차이를 보고한다. |
| “길이가 줄어도 답을 못 하면 의미 없다.” | 정확도 비열등성·미완료율을 동시에 본다. 짧아졌다는 이유만으로 성공 처리하지 않는다. |
| “토큰 cap에 걸린 모델을 더 오래 생각했다고 하면 안 된다.” | 실제 소비량과 완성된 길이를 구분한다. cap 비율을 기록하고, cap 지배 조건은 연구 범위를 제한하거나 중단한다. |
| “negative result는 기존 사실의 재확인이다.” | 위험이 있다. 충분히 작은 효과 상한, 다른 조건 재현, 정당한 개입 검증이 있어야 기여 후보가 된다. 한 셀의 p>0.05는 불충분하다. |
| “동일 seed가 동일한 랜덤 실험을 보장하나?” | 아니다. 샘플러 구현·GPU 수치 차이를 기록하고 paired 단위는 문제로 잡는다. 공통 난수와 일반 seed 반복을 구분한다. |
| “4-bit에서는 길이가 안 늘 수도 있다.” | 해당 셀은 진단 경계다. R을 억지로 계산하거나 결과를 숨기지 않는다. |
| “3-bit에서만 보이면 일반적 가치가 낮다.” | 맞다. 결론을 공격적 양자화에 한정한다. 4-bit/7B 재현 여부에 따라 기여의 범위를 축소한다. |
| “4090 두 장이면 무조건 충분하다는 계산인가?” | 아니다. dual-model forward와 긴 생성이 병목이다. 실제 처리량을 측정한 뒤 일정 관문을 통과해야 한다. |
| “검색에서 못 찾았다고 새 주제라 할 수 있나?” | 없다. 검색 범위를 공개하고 직접 읽은 핵심 연구와 비교한다. 일부 검색이 일반 페이지로 확장된 것은 신규성 증거로 쓰지 않는다. |

## 기존 조사에서 바로 받아들이지 않은 주장

- ‘가설이 맞든 틀리든 논문이 된다’는 보장은 채택하지 않는다.
- ‘양자화와 같은 평균 KL을 갖는 Gaussian 노이즈면 공정한 대조다’는 충분하지 않다. 위치별 오차·공분산·시계열 의존성이 다를 수 있다.
- 무작위 가중치 노이즈가 모든 prefix의 엔트로피를 반드시 올린다는 일반 명제는 성립하지 않는다. 온도 증가와 가중치 교란을 같은 조작으로 취급하지 않는다.
- 표현을 평균값으로 바꾸어도 성능이 같다는 실험은 이미 register 문헌에 존재한다. 대상만 바꾸어 새 H1이라고 단정하지 않는다.
- 32K 토큰 생성이 포함된 수천 시행을 처리량 측정 없이 ‘하루면 된다’고 계산하지 않는다.

## 최종 판정 규칙

**지금의 GO는 교수님께 제출할 가치가 있다는 뜻이다.** 실험 GO는 승인·재현·처리량·검정력 관문을 통과한 다음이다. 논문 완성 가능성은 결과와 재현을 보고 별도로 판단한다.

H1의 긍정 결과를 강하게 예상할 근거는 현재 부족하다. 그렇지만 두 경로를 직접 교환할 수 있다는 점 때문에 실행 가능한 원인 분해 후보로 남긴다. 이 판단보다 강한 보장을 요청받더라도 근거 없이 확률을 붙이지 않는다.
